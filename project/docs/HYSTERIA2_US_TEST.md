# Прямой тест Hysteria2 на США

## Назначение

Изолированный эксперимент 09.09.2026 для подключения к США через QUIC/UDP,
когда прямые VLESS REALITY и WS с телефона не работают. Не заменяет Xray
и не меняет рабочий резерв через TR. Результат с телефона нужно подтвердить
отдельно от серверных проверок.

## Размещение

- США: `82.38.60.90`, TLS-имя `serghexen.ru`.
- Внешний порт: **443/UDP**, контейнер слушает 2443/UDP.
- Существующий Xray продолжает использовать **443/TCP**.
- Отдельный каталог: `/opt/hexenvpn-hysteria`.
- Compose project: `hexenvpn-hysteria`, контейнер: `hexenvpn-hysteria-test`.
- Образ: Hysteria `v2.12.2`, digest закреплён в `hysteria.env`.
- Авторизация: отдельный случайный пароль, обфускация Salamander с другим
  случайным паролем. В Git и журналы пароли не выводить.

Конфигурация в репозитории:

- `project/docker-compose.master-hysteria.yml`;
- `project/hysteria/server.example.json`;
- `project/env/hysteria.env.example`.

В отдельном каталоге сервера сохранена та же структура `project/...`.
Рабочие файлы: `project/hysteria/server.json` и `project/env/hysteria.env`.
Они содержат секреты либо настройки экземпляра, права 0600. Родительский
каталог `/opt/hexenvpn-hysteria` имеет права 0700.

## Изоляция

Лимиты тестового контейнера: 192 MiB RAM, 0.5 CPU, 64 процесса;
логи ограничены двумя файлами по 5 MiB. Root filesystem только для чтения,
capabilities удалены, `no-new-privileges` включён, Docker socket не монтируется.
Сертификат и ключ монтируются только для чтения из существующих каталогов
Let's Encrypt конкретного домена. Hysteria перечитывает сертификат при
новых TLS-handshake; nginx/certbot для теста не менялись.

ACL запрещает распространённые локальные, частные и link-local диапазоны.
Это не замена полноценной сетевой изоляции для многопользовательского сервиса.
Запросы остаются защищены авторизацией. У сервера INPUT ACCEPT, UFW отсутствует;
новых ручных firewall-правил не добавляли, UDP публикует Docker.
Firewall панели провайдера отдельно не проверен.

`ignoreClientBandwidth=true` исключает запрашиваемый клиентом Brutal-режим.
Это не ограничитель расхода трафика. Лимиты CPU/RAM выбраны для эксперимента,
не для измерения максимальной скорости.

## Проверка и управление

```bash
cd /opt/hexenvpn-hysteria
docker compose -p hexenvpn-hysteria --env-file project/env/hysteria.env \
  -f project/docker-compose.master-hysteria.yml ps
docker logs --tail 30 hexenvpn-hysteria-test
```

Проверять не только открытый UDP-порт: клиент должен установить QUIC-туннель
с проверкой сертификата и выполнить HTTPS-запрос с выходом `82.38.60.90`.
Дополнительно проверить отказ с неверным паролем и запрет локальных адресов.
После этого тестировать в Happ с телефона через Wi-Fi и мобильную сеть.
Не отключать проверку TLS-сертификата в приложении.

Проверка 09.09.2026 выполнена временным клиентом на TR: QUIC/UDP до США
успешен, HTTPS вернул `82.38.60.90`, неправильный пароль и запрос
`http://127.0.0.1:80` отклонены. Временные контейнеры и секретные файлы клиента
удалены. Образ клиента остался в Docker cache TR. Рабочие сервисы TR не менялись.
После проверки Hysteria на США использовала около 3.4 MiB RAM в покое.
Исходные конфиги прошли сверку SHA-256, Xray и бот не перезапускались.
Тестовая подписка выдаётся через TR; её профиль подключается напрямую
к `82.38.60.90:443/UDP`, TR не участвует в VPN-трафике этого профиля.
Путь к созданному файлу хранится в `/opt/hexenvpn-hysteria/test-sub-file`.

Пользователь сообщил: в Happ Android 4.3.0 профиль импортирован, но пинга
и доступа к сайтам нет. Во время согласованной повторной попытки наблюдение
на внешнем интерфейсе США не зарегистрировало UDP-пакетов телефона на 443.
Контрольный UDP-пакет с TR зарегистрирован, сбор работает. Это не доказывает
блокировку UDP: ещё возможны ошибка запуска протокола в клиенте или проблема
маршрутизации на устройстве. Запрошен журнал Happ. Не распространять профиль
на остальных пользователей до успешного клиентского теста.

## Ограничения теста

Доступ предназначен только владельцу и выдаётся отдельной тестовой подпиской.
Он **не интегрирован** с БД бота, оплатой, сроками, лимитом устройств и сбором
трафика Xray. Блокировка пользователя ботом не отзывает этот отдельный пароль.
Не распространять тестовую ссылку другим пользователям. До промышленного
использования нужна интеграция выдачи и отзыва доступа.

## Откат

### Дополнительный тест без Salamander

После неуспешного подключения с телефона добавлен отдельный вариант
**2443/UDP без обфускации**, для проверки именно домашнего Wi-Fi.
Это комбинированный тест порта и обфускации: если он заработает, нужно
отдельно проверить, какой из двух параметров повлиял.

- Compose: `project/docker-compose.master-hysteria-plain.yml`.
- Project name: `hexenvpn-hysteria-plain` (не имя первого теста).
- Контейнер: `hexenvpn-hysteria-plain-test`.
- Конфиг: `project/hysteria/server-plain.json`, права 0600, отдельный пароль.
- Создан из `server.json` удалением блока `obfs` и заменой пароля;
  TLS, ACL и ограничения ресурсов сохранены.
- Тестовая ссылка не содержит `obfs` и `obfs-password`.
- Существующий UDP 443 с Salamander не изменялся.

Для остановки именно второго теста:

```bash
cd /opt/hexenvpn-hysteria
docker compose -p hexenvpn-hysteria-plain --env-file project/env/hysteria.env \
  -f project/docker-compose.master-hysteria-plain.yml down
```

Путь к его отдельному файлу подписки записан в
`/opt/hexenvpn-hysteria/test-sub-plain-file` после публикации.
Не подключать этот статический доступ к остальным пользователям.

### Первый тест с Salamander

```bash
cd /opt/hexenvpn-hysteria
docker compose -p hexenvpn-hysteria --env-file project/env/hysteria.env \
  -f project/docker-compose.master-hysteria.yml down
```

Удаляется только отдельный контейнер и его сеть; TCP Xray, nginx, бот,
сертификаты и БД не затрагиваются. После теста также удалить конкретный файл
`/var/www/sub/test-hy2-<токен>` на мастере и тестовую подписку в приложении.
Перезапуск всего Docker или ВМ для отката не требуется.

Исходные SHA-256 конфигов Xray, nginx и clients.json сохранены отдельно
в `/opt/hexenvpn-hysteria/baseline.json`; это контроль изменений, не полный бэкап.
