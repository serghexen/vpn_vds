## Что обновить

1. Владелец меняет IP в панели и сообщает новый адрес.
2. Проверить SSH `adminops@<новый_IP>` по существующему ключу.
   Ожидается тот же host key; текущий сохранён под `139.60.163.205`.
   Не отключать StrictHostKeyChecking и не удалять known_hosts вслепую.
3. Владелец обновляет A-записи `serghexen.ru` и `23pr.serghexen.ru`.
   Запись `tr.serghexen.ru` не менять. Сертификат домена перевыпускать
   только из-за смены IP не требуется.
4. На TR заменить upstream IP в двух файлах, предварительно сохранив копии:
   `/etc/nginx/snippets/hexenvpn-subscription-relay.conf` и
   `/etc/nginx/snippets/hexenvpn-us-relay.conf`.
   SNI/Host оставить `serghexen.ru`, TLS verify не отключать.
   Проверить `nginx -t`, затем выполнить reload, не рестарт Xray.
5. В `/opt/hexenvpn-hysteria/project/env/hysteria.env` обновить
   `HYSTERIA_BIND_IP`. Если тесты сохраняем, пересоздать только два отдельных
   Hysteria Compose-проекта, не основной master Compose.
6. Только два тестовых Hysteria-профиля содержат старый IP буквально;
   обновить их с бэкапом либо убрать после согласованного завершения тестов.
   Обычные профили при подготовительной проверке использовали домен.

## Проверки после смены

- SSH, фактический адрес интерфейса, маршрут наружу.
- Xray и бот запущены, nginx отвечает, UUID и БД сохранены.
- HTTPS подписок с проверкой сертификата напрямую и через TR.
- Реальный трафик через США, TR и резерв TR -> США.
- Прямое подключение пользователя к США именно с домашнего Wi-Fi.

До обновления upstream на TR временно не работают США через TR и relay
подписок. Обычная Турция не зависит от смены IP мастера для уже выданного
профиля и не должна требовать перезапуска. Успех прямого подключения на
новом IP заранее не гарантируется.
