# Резервная подписка через Турцию

## Назначение

Добавлено 09.09.2026 для проверки и обхода недоступности адреса мастера
с телефона. Перезагрузка мастера и исправление его сертификата не устранили
сообщаемый пользователем таймаут. Серверные проверки при этом успешны.
Точная причина таймаута на телефоне пока не установлена.

Схема:

```text
Телефон -> HTTPS tr.serghexen.ru:2053 -> HTTPS serghexen.ru:8443 -> подписка
```

Резервный адрес возвращает данные существующего мастера, без отдельной БД,
копирования пользователей и изменения их UUID. Он помогает при недоступности
мастера со стороны клиента, но не при остановке самого мастера.

## Адреса

- Проверка доступности: `https://tr.serghexen.ru:2053/support`.
- Подписка: `https://tr.serghexen.ru:2053/sub/<существующий_код_или_имя>`.
- Основной адрес `https://serghexen.ru:8443/sub/...` сохранён.
- Автоматическая замена ссылок в боте и у пользователей не выполнялась.

В исходной ссылке подписки заменяется только `https://serghexen.ru:8443`
на `https://tr.serghexen.ru:2053`, а путь `/sub/...` сохраняется.
Это ссылка для импорта по URL, а не адрес страницы с инструкцией `/i/...`.
Корень `/` и страница `/i/...` на резервном адресе не опубликованы и дают 404.

## Развёртывание

Шаблон: `project/nginx/subscription-relay.locations.conf.template`.
Подстановки текущего мастера:

- `__MASTER_IP__`: `82.38.60.90`
- `__MASTER_SUB_PORT__`: `8443`
- `__MASTER_DOMAIN__`: `serghexen.ru`

На TR отрендеренный файл расположен в
`/etc/nginx/snippets/hexenvpn-subscription-relay.conf`.
В существующий server block `/etc/nginx/conf.d/hexenvpn-tr-ws.conf`
добавлена строка:

```nginx
include /etc/nginx/snippets/hexenvpn-subscription-relay.conf;
```

Применение: `nginx -t && systemctl reload nginx`.
Путь `/api/v1/stream` и Xray-конфиг не изменялись.
Подключение TR к мастеру проверяет TLS-сертификат и имя `serghexen.ru`;
проверка сертификата не отключается. При смене IP мастера обновить relay-файл.

Доступны только GET/HEAD для `/support` и `/sub/<код>`.
Кэширование выключено. User-Agent и HWID-заголовки передаются мастеру.
В дополнительный access log TR адреса подписок не записываются.
Мастер продолжает вести свой журнал. На сетевом уровне он видит IP TR;
настройка доверенных real-IP заголовков мастера в этом изменении не менялась.

## Проверки и откат

Проверено извне: HTTPS без ошибок сертификата; `/support` возвращает 200;
подписка для Happ и v2rayTun содержит четыре профиля и побайтно совпадает
с ответом мастера, включая сохранение `Subscription-Userinfo`.
Неизвестные пути возвращают 404, POST запрещён (403).
Пользователь подтвердил загрузку текста `/support` на телефоне.
Обновление подписки в Happ через резервный URL ещё требует проверки пользователем.

Резервная копия на TR:
`/root/backup-subscription-relay-20260909T051131Z/hexenvpn-tr-ws.conf`.

Для отката сразу после изменения, если конфиг с тех пор не менялся:

```bash
sudo cp -a /root/backup-subscription-relay-20260909T051131Z/hexenvpn-tr-ws.conf \
  /etc/nginx/conf.d/hexenvpn-tr-ws.conf
sudo nginx -t && sudo systemctl reload nginx
```

Если позже были другие правки, удалить только строку include relay-файла,
проверить `nginx -t` и выполнить reload. Перезапуск Xray не нужен.
